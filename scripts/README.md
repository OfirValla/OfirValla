# How this profile is built

Everything on the profile page is an SVG in `assets/`, generated by the scripts in this folder.
There are no runtime dependencies, just Node 20+.

| File | What it does |
| --- | --- |
| `profile.config.mjs` | All the text: name, typing lines, tech stack, projects, "currently exploring" |
| `build-assets.mjs` | Renders the header, section titles, stack, project cards, exploring tiles and footer |
| `update-stats.mjs` | Pulls stats from the GitHub GraphQL API and renders the two stats cards |
| `update-activity.mjs` | Rewrites the list between the `ACTIVITY` markers in `README.md` |
| `lib/` | Theme tokens, SVG helpers and the stats card renderer |
| `icons/brand`, `icons/ui` | Vendored logos ([devicon](https://devicon.dev), MIT) and UI icons ([lucide](https://lucide.dev), ISC) |

Every asset comes in a `-dark` and a `-light` version; the README picks one with `<picture>` based on the
viewer's GitHub theme.

## Making changes

```bash
npm run build       # after editing profile.config.mjs
npm run activity    # works without a token
GITHUB_TOKEN=... npm run stats
```

Pushing changes under `scripts/` also triggers the workflow, which rebuilds everything and commits the result,
so editing the config on github.com is enough.

- **Text wrapping:** SVG can't wrap text, so descriptions are written as separate lines. Keep project lines under
  ~58 characters and exploring lines under ~52.
- **Adding a project:** add it to `projects` in the config, then copy one of the `<a href=...><picture>` lines in
  `README.md` and change the repo link and file names.
- **New stack icon:** drop a devicon SVG into `icons/brand/` and reference its file name.

## Automation

`.github/workflows/refresh-profile.yml` runs every 6 hours, on every push that touches `scripts/`, and on demand
(Actions tab → Refresh profile → Run workflow). It only commits when something actually changed.

GitHub pauses scheduled workflows after 60 days without repository activity. If the stats stop updating,
re-enable the workflow from the Actions tab.

## Counting private repositories

By default the stats use the workflow's built-in token, which only sees public data. To include private work:

1. Create a fine-grained personal access token with read-only access to **Contents** and **Metadata** on all your
   repositories.
2. Add it as a repository secret named `PROFILE_TOKEN`.
3. Set `stats.includePrivate: true` in `profile.config.mjs`.

To have private contributions show up in the contribution count, also enable **Include private contributions on my
profile** in your GitHub profile settings.
